- **The recorder's failure reaches the supervisor late.** `recorder.failure()` (an event given up on, or an invalid emitted one) is read once per supervisor loop pass, so a running worker's later events are still stored until some thread ends, past the gap. Give the recorder an `onFailure` callback (as `onLeaseLost`) that the supervisor wires to its `fail()`, and refuse new events once it is set. Also read `events.failure()` after the final flush in `apps/runner/src/run.ts`, since events emitted after the supervisor's last check are only logged.
