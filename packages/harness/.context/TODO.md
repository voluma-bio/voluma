- **The recorder's failure reaches the supervisor late.** `recorder.failure()` (an event given up on, or an invalid emitted one) is read once per run-loop step, so a running worker's later events are still stored until some thread ends, past the gap. Give the recorder an `onFailure` callback (as `onLeaseLost`) that the run loop wires to its `fail()`, and refuse new events once it is set. Also read `events.failure()` after the final flush in `apps/runner/src/run.ts`, since events emitted after the run loop's last check are only logged.
- **Two run-loop guarantees fail on the faux stream** (`src/run-loop.test.ts`, the two `it.fails` tests; remove `.fails` when fixed):
  - A stale mark does not stop the idle worker of a `done` or `to-check` dependent (`staleDependents` picks the thread to stop from the task's status: `in-progress` worker, `under-review` check). The stale task's `start_worker` is then refused ("has a worker (idle)") until main calls `stop_worker`.
  - A cut-off between a feedback `message`'s `attempt.opened` and the worker's copy of the text leaves the worker idle on an open attempt; `interruptedResult` tells main the `message` completed, and nothing resumes an idle holder, so the run ends by the liveness rule.
- **A checker waiting on an unanswered `ask` has no deadline in practice.** Liveness ("no worker or checker running") counts it as not running, so a main that only waits gets two wakes and the run ends before `checkTimeoutMs`.
